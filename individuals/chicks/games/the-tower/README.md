# The Tower

This is a game that baffles everyone who sees me playing it. I'm sure they'd
be even more baffled to discover I've been tracking my matches to discern any
signs of progress. I was able to gain some insights from this spreadsheet
itself, but I knew I wanted to eventually generate some scatter plots and
trend lines. Here it is.

## Playlog quirks

The playlog is a manual spreadsheet export from the game, and
`analysis/analyze-playlog.R` already accounts for everything below. None
of these are defects, and reviewers of routine update PRs shouldn't flag
them:

- **Tiny coin values on dissonant runs are real.** Dissonant Utility runs
  legitimately produce values like `Total Coins (B)` = `0.000000036` and
  `Minutes/Billion` in the hundreds of millions — dissonance suppresses
  coin income by orders of magnitude. They're not unit or data-entry
  errors. The recent stats table (regular and attack rows) already
  filters `Minutes/Billion` to under 100 and leaves out the non-attack
  dissonant categories, and the dissonant tables use Finish/Max Wave
  instead of coin columns, so nothing needs excluding. (A wildly off
  value on a *regular* run would still be worth a look.)
- **Huge coin values on attack dissonant runs are real, too.** Attack
  dissonance goes the other way and boosts coin income, so the `Attack`
  rows in the recent stats table legitimately show `Avg Min/B` around
  0.01–0.05 and `Avg Coins/Hr` in the thousands, far beyond the regular
  rows for the same tier. That's the whole point of farming them, not a
  data-entry error.
- **`#N/A` tokens and blank trailing rows are export artifacts.**
  `parse_numeric()` turns spreadsheet error tokens into NA, and rows
  without a Date are filtered out. The blank placeholder rows at the end
  of the TSV get filled in by future updates, so a near-zero net change
  in TSV line count is normal.
- **Rows aren't in strict chronological order.** The log is entered by
  hand. The analysis sorts by date (`arrange()`) or lets ggplot2 order
  the date axis, and "latest run" means max Date, not last row.
- **`Pct of Max` above 100% is expected.** `Max Wave` is exported from
  the spreadsheet as-is; the script derives `Pct of Max` as
  `Finish Wave / Max Wave`. A newer run can beat a max that was set
  earlier or by another category.
- **A blank `Dissonant Run` cell means a regular run.** The column is
  only populated for dissonant runs (Attack, Defense, Utility, Ultimate
  Weapons).
- **Negative tiers are tournaments** (`-8`, `-12`, …).
- **The stats windows shift every update.** "Recent" stats start on the
  first day of the month 4 months before the latest run, so they can
  span 5 calendar months (e.g. Jul–Nov); the tournament window uses the
  same rule with a 6-month offset, and the 2-month graph
  (`minutes-per-billion-by-tier-2mo.png`) uses a 2-month one. Counts and
  totals dropping between PRs is the window moving, not lost data. (The
  min/B zoom graph, `minutes-per-billion-by-tier-zoom.png`, is the
  exception: it starts at a fixed 2025-09-01, so it grows but never
  shifts.)

If `analyze-playlog.R` changes any of this behavior, update this section
in the same PR.
